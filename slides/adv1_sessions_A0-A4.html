A0 — Projet reproductible

Reproductible = relancer et retrouver les mêmes résultats

Ce qui casse la reproductibilité :

  1. des chemins propres à un ordinateur : setwd("C:/Users/Rakoto/...")
  2. des étapes manuelles (Excel, copier-coller, clic droit → enregistrer)
  3. des logiciels qui changent (versions des packages)
Test ultime : supprimer outputs/, redémarrer R, lancer 00_run_all.R… tout revient ?

Une arborescence claire

reef-monitoring/
├── reef-monitoring.Rproj     README.md
├── data/raw/       <- tels que reçus, JAMAIS modifiés
├── data/derived/   <- produits par les scripts
├── R/00_run_all.R  01_import.R  02_clean.R  03_analysis.R  04_figures.R
├── reports/        <- .Rmd / .qmd
└── outputs/figures/  outputs/tables/
  • noms : minuscules, sans espaces ni accents, dates aaaa-mm-jj, scripts numérotés
  • les versions : Git, pas _v2_FINAL

Chemins : here() plutôt que setwd()

library(here)
reef <- read.csv(here("data", "raw", "reef_monitoring.csv"))
  • here() part de la racine du projet (fichier .Rproj), même depuis reports/
  • ne jamais enregistrer .RData ; redémarrer R souvent (Ctrl + Maj + F10)
  • sessionInfo() → outputs/session_info.txt

A1 — renv

Une bibliothèque par projet

Étape Fonction
démarrer renv::init()
enregistrer les versions renv::snapshot() → renv.lock
vérifier renv::status()
réinstaller (autre ordinateur) renv::restore()
À partager : renv.lock, .Rprofile, renv/activate.R. Jamais renv/library/.

Lire un fichier lock

A2 — Git, GitHub, GitLab avec RStudio

Le vocabulaire

Mot Sens
dépôt (repo) dossier suivi par Git (.git/)
commit instantané + message + auteur + date, sur votre ordinateur
push envoyer vos commits vers GitHub / GitLab
pull récupérer les commits des autres
clone copier un dépôt en ligne sur votre ordinateur
Pas de données personnelles ni de gros fichiers dans un dépôt — surtout public.

Une seule fois par ordinateur

  1. Installer Git for Windows (éditeur : Notepad · branche : main · Git Credential Manager)
  2. RStudio : Tools → Global Options → Git/SVN → git.exe ; Terminal → Git Bash
  3. Terminal de RStudio :
git config --global user.name "Prénom Nom"
git config --global user.email "adresse@du.compte"
git config --global init.defaultBranch main
  1. Comptes GitHub et GitLab (double authentification, garder les codes de secours)

Du site à RStudio

  1. Sur le site : New repository → nom, Private, Add a README → copier l’URL HTTPS
  2. RStudio : File → New Project → Version Control → Git → coller l’URL
  3. Dossier hors de OneDrive · le panneau Git apparaît
Statut Sens
? nouveau, pas encore suivi
M modifié
A / D ajouté / supprimé

Le cycle de travail

  • Pull en ouvrant le projet
  • travailler, enregistrer
  • Commit : cocher Staged, écrire un message clair, Commit — une modification logique = un commit
  • Push à la fin de la séance (ou quand un collègue en a besoin)
  • Push rejeté ? → Pull, puis Push
  • premier Push : la fenêtre Git Credential Manager demande de se connecter

A3 — R Markdown

Le rapport EST l’analyse

  • en-tête YAML + texte Markdown + chunks R
  • Knit = nouvelle session vide → tout doit être créé dans le .Rmd
  • options : echo, include, eval, message, warning, fig.cap, fig.width

Code en ligne : `r nt` → « 37.6 % dans les zones No-take »

A4 — Rapports automatiques

Un modèle, des paramètres

params:
  mpa: "Ankaramena"
  year: 2025
  • dans le rapport : params$mpa, params$year
  • Knit with Parameters : formulaire (listes déroulantes avec input: select)
  • phrases robustes : if … else quand l’année précédente manque

Un rapport par AMP, en un clic

for (m in c("Ankaramena", "Nosy Fasika", "Tanjona")) {
  rmarkdown::render(here::here("reports", "mpa_report.Rmd"),
                    params = list(mpa = m, year = 2025),
                    output_file = paste0("report_", gsub(" ", "_", tolower(m)), "_2025.html"),
                    output_dir = here::here("outputs", "reports"),
                    envir = new.env())        # départ propre pour chaque rapport
}

Chaque année : nouvelles données dans data/raw/ → 00_run_all.R → render_reports.R → commit → envoi.
