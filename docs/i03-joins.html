I3 · Joining tablesI3 · Joindre des tableaux

~3 h

By the end of this session you will be able to

  • explain what a key is and check that it is unique;
  • combine tables with left_join(), inner_join(), full_join() and base R merge();
  • find the rows that do not match with anti_join();
  • join on several keys (zone + year + month) and check the result;
  • build the single analysis table used in the next sessions.

À la fin de cette séance vous saurez

  • expliquer ce qu’est une clé et vérifier qu’elle est unique ;
  • combiner des tableaux avec left_join(), inner_join(), full_join() et merge() de R de base ;
  • trouver les lignes qui ne correspondent pas avec anti_join() ;
  • joindre sur plusieurs clés (zone + année + mois) et vérifier le résultat ;
  • construire le tableau d’analyse unique utilisé dans les séances suivantes.

⇩ checkpoint: I1_lines_dated.csv ⇩ checkpoint: I0_farmers.csv ⇩ checkpoint: I2_water_quality_monthly.csv

Why several tables?Pourquoi plusieurs tableaux ?

Good field databases avoid repeating information. The technician did not type the village, sex and technique of the farmer on each of the 2 575 lines: he typed them once in the farmers sheet, and each line only carries the farmer_id. That column is a key: it links the two tables. To analyse growth by sex or technique, we must bring the farmer information next to each line — a join.

Les bonnes bases de données de terrain évitent de répéter l’information. Le technicien n’a pas saisi le village, le sexe et la technique du producteur sur chacune des 2 575 lignes : il les a saisis une fois dans la feuille farmers, et chaque ligne ne porte que le farmer_id. Cette colonne est une clé : elle relie les deux tableaux. Pour analyser la croissance par sexe ou par technique, il faut amener l’information du producteur à côté de chaque ligne — une jointure.

Simulated context of villages.csv. When the cooperative was created, the technician recorded with a handheld GPS the position (longitude, latitude, WGS84) of the landing beach of each of the 12 villages, and assigned each village to a zone (North, Centre, South) used by the NGO for the water-quality stations. Type of data: reference table (one row per village), spatial coordinates.

Contexte simulé de villages.csv. À la création de la coopérative, le technicien a relevé au GPS la position (longitude, latitude, WGS84) de la plage de débarquement de chacun des 12 villages, et attribué chaque village à une zone (Nord, Centre, Sud) utilisée par l’ONG pour les stations de qualité de l’eau. Type de données : table de référence (une ligne par village), coordonnées spatiales.

Keys must be unique on one sideLes clés doivent être uniques d’un côté

Before joining, check that the key identifies one row in the reference table. Otherwise each line would be copied several times.

Avant de joindre, vérifiez que la clé identifie une seule ligne dans la table de référence. Sinon chaque ligne serait copiée plusieurs fois.

library(dplyr)
sum(duplicated(farmers$farmer_id))        # 0: one row per farmer
#> [1] 0
all(lines$farmer_id %in% farmers$farmer_id)   # every line has a known farmer
#> [1] TRUE

The four main joinsLes quatre jointures principales

Function Keeps Typical use
left_join(x, y) all rows of x, with y added where the key matches (NA otherwise) add information to your main table — the most used
inner_join(x, y) only rows whose key is in both analyse only complete cases
full_join(x, y) all rows of both compare two lists
anti_join(x, y) rows of x with no match in y find errors: unknown ids, missing records
Fonction Garde Usage typique
left_join(x, y) toutes les lignes de x, avec y ajouté quand la clé correspond (NA sinon) ajouter de l’information à votre tableau principal — la plus utilisée
inner_join(x, y) seulement les lignes dont la clé est dans les deux analyser seulement les cas complets
full_join(x, y) toutes les lignes des deux comparer deux listes
anti_join(x, y) les lignes de x sans correspondance dans y trouver les erreurs : identifiants inconnus, enregistrements manquants 
lf <- left_join(lines, farmers, by = "farmer_id")

merge() sorts the result by the key; left_join() keeps the original order. all = TRUE gives a full join, all.y = TRUE a right join, nothing an inner join.

merge() trie le résultat par la clé ; left_join() garde l’ordre d’origine. all = TRUE donne une jointure complète, all.y = TRUE une jointure à droite, rien une jointure interne.

Functions and arguments used here

Function / argument What it does Value it expects
left_join(x, y, by), inner_join(), full_join(), anti_join() join two tables (see the table above for what each one keeps)
  x, y the first (main) table and the table whose information is added data frames
  by the key column(s), present in both tables. Several keys: c("zone", "year", "month"). Different names in the two tables: c("name_in_x" = "name_in_y") column names in quotes
merge(x, y, by, all.x, all.y, all) base R join; all.x = TRUE keeps all rows of x (left join), all.y = TRUE all rows of y, all = TRUE both (full join); none = inner join TRUE / FALSE

Fonctions et arguments utilisés ici

Fonction / argument Ce qu’il fait Valeur attendue
left_join(x, y, by), inner_join(), full_join(), anti_join() joignent deux tableaux (voir le tableau ci-dessus pour ce que chacune garde)

Same job, different vocabulary: dplyr has one function per type of join, merge() has one function with switches (all.x, all.y, all). Both use by for the key.

Même travail, vocabulaire différent : dplyr a une fonction par type de jointure, merge() a une seule fonction avec des interrupteurs (all.x, all.y, all). Les deux utilisent by pour la clé.

Finding problems with anti_join()Trouver les problèmes avec anti_join()

The survey (Session I4) has a household table and a member table linked by hh_id. Members whose household does not exist reveal typing errors:

L’enquête (séance I4) a un tableau des ménages et un tableau des membres reliés par hh_id. Les membres dont le ménage n’existe pas révèlent des erreurs de saisie :

hh <- read.csv("data/survey_households.csv")
members <- read.csv("data/survey_members.csv")
anti_join(members, hh, by = "hh_id")
#>   hh_id member_no relation sex age in_school works_seaweed
#> 1 HH901         1     head   F  63                      no
#> 2 HH903         2    other   M  59                      no
#> 3 HH904         3    child   M  22                      no
#> 4 HH902         3    other   M  18                      no

A join that adds rows is a red flag. If hh contains a household twice (duplicated interview), every member of that household will be copied twice after the join. Always compare nrow() before and after, and check sum(duplicated(key)) on the reference table.

Une jointure qui ajoute des lignes est un signal d’alerte. Si hh contient un ménage en double (entretien saisi deux fois), chaque membre de ce ménage sera copié deux fois après la jointure. Comparez toujours nrow() avant et après, et vérifiez sum(duplicated(cle)) sur la table de référence.

sum(duplicated(hh$hh_id))
#> [1] 5
nrow(members); nrow(left_join(members, hh, by = "hh_id"))
#> [1] 2348

Joining on several keysJoindre sur plusieurs clés

To relate growth to sea temperature, we need the mean temperature of the zone of the village, in the month of planting. The water-quality summary from Session I2 has one row per zone, year and month: the join uses three keys at once.

Pour relier la croissance à la température de l’eau, il faut la température moyenne de la zone du village, le mois du semis. Le résumé de qualité de l’eau de la séance I2 a une ligne par zone, year et month : la jointure utilise trois clés à la fois.

villages <- read.csv("data/villages.csv")
wq_month <- cp_wq_monthly()                   # = I2_water_quality_monthly.csv
head(wq_month, 3)
#>     zone year month temp_mean sal_mean
#> 1 Centre 2023     1  27.85000  33.8250
#> 2 Centre 2023     2  29.12857  33.5625
#> 3 Centre 2023     3  28.32500  33.6625
seaweed <- lines %>%
  left_join(farmers, by = "farmer_id") %>%
  left_join(villages[, c("village", "zone")], by = "village") %>%
  left_join(wq_month[, c("zone", "year", "month", "temp_mean")],
            by = c("zone", "year", "month"))
dim(seaweed)
#> [1] 2575   23
sum(is.na(seaweed$temp_mean))                 # 0: every line found its temperature
#> [1] 0

by = c("zone", "year", "month") rows are matched only when the three keys are equal

When the key has different names in the two tables: by = c("village" = "village_name"). In merge(): by.x = "village", by.y = "village_name".

Quand la clé a des noms différents dans les deux tableaux : by = c("village" = "village_name"). Dans merge() : by.x = "village", by.y = "village_name".

Question 7 : comparez nrow(left_join(members, hh, by = "hh_id")) avec nrow(members). Question 9 : anti_join(households, assets, by = "hh_id") garde les ménages absents du tableau des biens.

library(dplyr)
lines    <- read.csv("data/checkpoints/I1_lines_dated.csv")
farmers  <- read.csv("data/checkpoints/I0_farmers.csv")
villages <- read.csv("data/villages.csv")
wq_month <- read.csv("data/checkpoints/I2_water_quality_monthly.csv")
seaweed <- lines %>%
  left_join(farmers, by = "farmer_id") %>%
  left_join(villages[, c("village", "zone")], by = "village") %>%
  left_join(wq_month[, c("zone", "year", "month", "temp_mean")], by = c("zone", "year", "month"))
ncol(seaweed)                                                          # 1
round(tapply(seaweed$sgr, seaweed$sex, mean, na.rm = TRUE), 3)         # 2
round(tapply(seaweed$sgr, seaweed$technique, mean, na.rm = TRUE), 3)   # 3
tapply(seaweed$sgr, seaweed$zone, mean, na.rm = TRUE)                  # 4
round(mean(seaweed$temp_mean[seaweed$village == "Lovobe"]), 3)         # 5

hh      <- read.csv("data/survey_households.csv")
members <- read.csv("data/survey_members.csv")
assets  <- read.csv("data/survey_assets.csv")
nrow(anti_join(members, hh, by = "hh_id"))                             # 6
nrow(left_join(members, hh, by = "hh_id")) - nrow(members)             # 7
hh <- hh[!duplicated(hh), ]
nrow(inner_join(members, hh, by = "hh_id"))                            # 8
nrow(anti_join(hh, assets, by = "hh_id"))                              # 9
