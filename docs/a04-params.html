A4 · Parameterised and automatic reportsA4 · Rapports paramétrés et automatiques

~3 h

By the end of this session you will be able to

  • turn a report into a template with params in its YAML header;
  • render it with chosen values: Knit with Parameters or rmarkdown::render(params = list(...));
  • produce one report per MPA (or per site, per year…) with a loop, with clear file names;
  • make the template robust (missing years, empty groups) and keep it short with your own functions;
  • organise an automatic reporting workflow that can be re-run every year.

À la fin de cette séance vous saurez

  • transformer un rapport en modèle avec params dans son en-tête YAML ;
  • le produire avec des valeurs choisies : Knit with Parameters ou rmarkdown::render(params = list(...)) ;
  • produire un rapport par AMP (ou par site, par année…) avec une boucle, avec des noms de fichiers clairs ;
  • rendre le modèle robuste (années manquantes, groupes vides) et le garder court avec vos propres fonctions ;
  • organiser une production automatique de rapports à relancer chaque année.

Data of this session (simulated). The same coral monitoring (Session A0). Each MPA manager wants a short report about her or his MPA only, every year, a few weeks after the field campaign — three reports per year, soon 2026, 2027… Writing them by hand would take days; with one parameterised template it takes one click. Note the gap in the data: Tanjona was not surveyed in 2022, so a report on Tanjona 2023 has no “previous year” to compare with — the template must handle it.

Données de cette séance (simulées). Le même suivi corallien (séance A0). Chaque gestionnaire d’AMP veut un court rapport sur son AMP seulement, chaque année, quelques semaines après la campagne de terrain — trois rapports par an, bientôt 2026, 2027… Les écrire à la main prendrait des jours ; avec un seul modèle paramétré, un clic suffit. Notez le trou dans les données : Tanjona n’a pas été suivie en 2022, donc un rapport Tanjona 2023 n’a pas d’« année précédente » à comparer — le modèle doit le gérer.

Parameters in the YAMLDes paramètres dans le YAML

Add a params: field to the header, with a default value for each parameter. Inside the report, params$mpa and params$year are used like any R value — to filter the data, in titles, in sentences.

Ajoutez un champ params: à l’en-tête, avec une valeur par défaut pour chaque paramètre. Dans le rapport, params$mpa et params$year s’utilisent comme n’importe quelle valeur R — pour filtrer les données, dans les titres, dans les phrases.

---
title: "`r paste('Monitoring report —', params$mpa)`"
author: "MPA monitoring team"
date: "`r format(Sys.Date(), '%d %B %Y')`"
params:
  mpa: "Ankaramena"
  year: 2025
output:
  html_document:
    toc: true
---

```{r setup, include=FALSE}
knitr::opts_chunk$set(echo = FALSE, message = FALSE, warning = FALSE, fig.width = 7, fig.height = 4)
library(dplyr); library(ggplot2); library(here)
reef  <- read.csv(here("data", "raw", "reef_monitoring.csv"))
sites <- read.csv(here("data", "raw", "reef_sites.csv"))
reef  <- left_join(reef, sites, by = "site_id")

# keep ONLY the MPA asked for in params
mine <- filter(reef, mpa == params$mpa)
now  <- filter(mine, year == params$year)
before <- filter(mine, year == params$year - 1)
m_now <- round(mean(now$hard_coral), 1)
m_before <- round(mean(before$hard_coral), 1)
```

Three things to notice: the title itself is computed (paste('Monitoring report —', params$mpa)); the data are filtered once, at the top, so the rest of the report does not need to know which MPA it is about; and the sentence about the previous year uses if … else (Intermediate, Session I5) so the report still makes sense when the previous year is missing.

Trois choses à remarquer : le titre lui-même est calculé (paste('Monitoring report —', params$mpa)) ; les données sont filtrées une seule fois, en haut, si bien que le reste du rapport n’a pas besoin de savoir de quelle AMP il s’agit ; et la phrase sur l’année précédente utilise if … else (intermédiaire, séance I5) pour que le rapport ait encore du sens quand l’année précédente manque.

Key (under each parameter) What it does Value it expects
params opens the list of parameters; each key under it (mpa, year) becomes params$mpa, params$year in the report names you choose (no spaces)
label text shown next to the field in the Knit with Parameters form text
value the default value, used when you click Knit or when render() gives no other value text, number, true/false

choices select only: the allowed values a list in brackets [a, b, c]
min, max, step slider and numeric only: smallest value, largest value, size of one step numbers

Rendering from codeProduire par le code

rmarkdown::render() does what the Knit button does, but you choose the parameters, the name and the folder of the output:

rmarkdown::render() fait ce que fait le bouton Knit, mais vous choisissez les paramètres, le nom et le dossier de la sortie :

rmarkdown::render(
  input       = here::here("reports", "mpa_report.Rmd"),
  params      = list(mpa = "Tanjona", year = 2023),     # replaces the default values
  output_file = "report_tanjona_2023.html",
  output_dir  = here::here("outputs", "reports"),
  envir       = new.env()                               # a clean environment for this report
)
Argument of render() What it does
input the .Rmd template
params a list() of values that replace the defaults of the YAML; parameters not given keep their default
output_file name of the result file (otherwise: the name of the .Rmd, so each report would overwrite the previous one)
output_dir folder of the result
envir the R environment in which the chunks run (see below)

Why envir = new.env()? By default render() runs the report in your current session: objects left by the previous report (or in your Environment) could be used by mistake. A new environment gives each report a clean start — exactly like the Knit button.

Argument de render() Ce qu’il fait
input le modèle .Rmd
params une list() de valeurs qui remplacent celles par défaut du YAML ; les paramètres non donnés gardent leur valeur par défaut
output_file nom du fichier résultat (sinon : le nom du .Rmd, et chaque rapport écraserait le précédent)
output_dir dossier du résultat
envir l’environnement R dans lequel les chunks s’exécutent (voir ci-dessous)

Pourquoi envir = new.env() ? Par défaut, render() exécute le rapport dans votre session courante : des objets laissés par le rapport précédent (ou dans votre Environment) pourraient être utilisés par erreur. Un nouvel environnement donne à chaque rapport un départ propre — exactement comme le bouton Knit.

One report per MPA, in one clickUn rapport par AMP, en un clic

# ==============================================================================
# render_reports.R — one report per MPA, in one click (Session A4)
# Run from the project root: source("R/render_reports.R")
# ==============================================================================
library(rmarkdown)
library(here)

mpas <- c("Ankaramena", "Nosy Fasika", "Tanjona")
dir.create(here("outputs", "reports"), recursive = TRUE, showWarnings = FALSE)

for (m in mpas) {
  file_name <- paste0("report_", gsub(" ", "_", tolower(m)), "_2025.html")   # no spaces in file names
  render(input       = here("reports", "mpa_report.Rmd"),
         params      = list(mpa = m, year = 2025),
         output_file = file_name,
         output_dir  = here("outputs", "reports"),
         envir       = new.env(),        # a clean environment for each report
         quiet       = TRUE)
  message("Done: ", file_name)
}

Robust templatesDes modèles robustes

A template is run on data you have not looked at. Protect it:

  • Check the parameters at the top: stopifnot(params$mpa %in% unique(reef$mpa)) stops with a clear message if somebody types “Ankaramenna”.
  • Handle empty data: if (nrow(now) == 0) { cat("No survey in", params$year); knitr::knit_exit() } ends the report politely.
  • Write sentences that work in every case (if … else in inline code, ifelse() for “increased” / “decreased”).
  • Put calculations in functions (R/functions.R, sourced by the template with source(here("R", "functions.R"))): the template stays short and the same function serves the reports, the scripts and the quizzes of your team.
  • Never write a number by hand in the template.

Un modèle s’exécute sur des données que vous n’avez pas regardées. Protégez-le :

  • Vérifiez les paramètres en haut : stopifnot(params$mpa %in% unique(reef$mpa)) s’arrête avec un message clair si quelqu’un tape « Ankaramenna ».
  • Gérez les données vides : if (nrow(now) == 0) { cat("Pas de suivi en", params$year); knitr::knit_exit() } termine le rapport proprement.
  • Écrivez des phrases qui marchent dans tous les cas (if … else dans le code en ligne, ifelse() pour « a augmenté » / « a diminué »).
  • Mettez les calculs dans des fonctions (R/functions.R, chargé par le modèle avec source(here("R", "functions.R"))) : le modèle reste court et la même fonction sert aux rapports, aux scripts et aux quiz de votre équipe.
  • N’écrivez jamais un nombre à la main dans le modèle.
# A sentence that adapts to the data (Intermediate, Session I6: functions)
trend_sentence <- function(now, before) {
  if (is.na(before)) return("There was no survey the year before.")
  d <- round(now - before, 1)
  paste0("Cover ", ifelse(d >= 0, "increased", "decreased"), " by ", abs(d),
         " points since the previous survey.")
}
trend_sentence(26.8, 24.6)
#> [1] "Cover increased by 2.2 points since the previous survey."
trend_sentence(27.5, NA)
#> [1] "There was no survey the year before."

Running it every yearLe relancer chaque année

With the structure of Sessions A0–A2, the yearly routine becomes:

  1. add the new field data to data/raw/ (a new file, or new rows — never overwriting the old ones);
  2. renv::restore() if you changed computer; run R/00_run_all.R, then R/render_reports.R with the new year;
  3. check one report carefully, commit (code + renv.lock, not the HTML files) and push;
  4. send the reports — or publish them online (Session A9).

Going further (optional): Windows Task Scheduler or cron (Mac/Linux) can run an R script at a fixed time, and GitHub Actions / GitLab CI can re-render reports each time you push — useful for a project website.

Avec l’organisation des séances A0–A2, la routine annuelle devient :

  1. ajouter les nouvelles données de terrain dans data/raw/ (un nouveau fichier, ou de nouvelles lignes — sans jamais écraser les anciennes) ;
  2. renv::restore() si vous avez changé d’ordinateur ; lancer R/00_run_all.R, puis R/render_reports.R avec la nouvelle année ;
  3. vérifier soigneusement un rapport, valider (code + renv.lock, pas les fichiers HTML) et pousser ;
  4. envoyer les rapports — ou les publier en ligne (séance A9).

Pour aller plus loin (facultatif) : le Planificateur de tâches de Windows ou cron (Mac/Linux) peuvent lancer un script R à heure fixe, et GitHub Actions / GitLab CI peuvent reproduire les rapports à chaque push — utile pour un site de projet.
