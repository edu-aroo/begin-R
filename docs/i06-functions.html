I6 · Writing your own functionsI6 · Écrire ses propres fonctions

~3 h

By the end of this session you will be able to

  • write a function with arguments, default values and a returned result;
  • check the arguments and stop with a clear message when they are wrong;
  • return several results in a list;
  • apply your function to each group with sapply(), tapply() or group_by();
  • keep your functions in a separate file and load them with source().

À la fin de cette séance vous saurez

  • écrire une fonction avec des arguments, des valeurs par défaut et un résultat renvoyé ;
  • vérifier les arguments et arrêter avec un message clair quand ils sont faux ;
  • renvoyer plusieurs résultats dans une liste ;
  • appliquer votre fonction à chaque groupe avec sapply(), tapply() ou group_by() ;
  • ranger vos fonctions dans un fichier séparé et les charger avec source().

⇩ checkpoint: I3_seaweed_analysis.csv

Why write functions?Pourquoi écrire des fonctions ?

Since Session I1 you compute the growth rate with 100 * log(final / initial) / days. You will need it again for the sea cucumbers of the final project, for each village, for a report… A function gives a name to this calculation: you write and check it once, and every use is short and identical. Rule of thumb: if you copied the same code three times, write a function.

Depuis la séance I1 vous calculez le taux de croissance avec 100 * log(final / initial) / days. Vous en aurez encore besoin pour les holothuries du projet final, pour chaque village, pour un rapport… Une fonction donne un nom à ce calcul : vous l’écrivez et la vérifiez une fois, et chaque utilisation est courte et identique. Règle pratique : si vous avez copié le même code trois fois, écrivez une fonction.

Anatomy of a functionAnatomie d’une fonction

sgr <- function(w_initial, w_final, days) {     # name <- function(arguments)
  100 * log(w_final / w_initial) / days         # the LAST value is returned
}
sgr(10, 25, 45)                                  # one line
#> [1] 2.036202
sgr(w_initial = 10, w_final = c(25, 30), days = 45)   # works on vectors too
#> [1] 2.036202 2.441361

  • The result is the last value computed. return(x) makes it explicit (useful to leave early).

Default valuesValeurs par défaut

Give an argument a default value with =: users can omit it. Here, a summary function with digits = 2 and na.rm = TRUE by default:

Donnez une valeur par défaut à un argument avec = : l’utilisateur peut l’omettre. Ici, une fonction de résumé avec digits = 2 et na.rm = TRUE par défaut :

describe <- function(x, digits = 2, na.rm = TRUE) {
  n  <- sum(!is.na(x))
  m  <- mean(x, na.rm = na.rm)
  s  <- sd(x, na.rm = na.rm)
  round(c(n = n, mean = m, sd = s, se = s / sqrt(n)), digits)
}
describe(seaweed$sgr)
#>       n    mean      sd      se 
#> 2317.00    3.44    0.67    0.01
describe(seaweed$sgr, digits = 4)
#>         n      mean        sd        se 
#> 2317.0000    3.4387    0.6659    0.0138

Checking the argumentsVérifier les arguments

A good function refuses wrong inputs with a clear message, instead of returning a silent wrong result. stop() stops with an error; warning() continues with a warning.

Une bonne fonction refuse les mauvaises entrées avec un message clair, au lieu de renvoyer un résultat faux en silence. stop() arrête avec une erreur ; warning() continue avec un avertissement.

sgr <- function(w_initial, w_final, days) {
  if (!is.numeric(w_initial) || !is.numeric(w_final)) stop("weights must be numbers")
  if (any(days <= 0, na.rm = TRUE)) stop("days must be positive")
  if (any(w_final > 100 * w_initial, na.rm = TRUE))
    warning("some final weights are > 100 x the initial weight: grams instead of kg?")
  100 * log(w_final / w_initial) / days
}
sgr("10", 25, 45)
#> Error in `sgr()`:
#> ! weights must be numbers
sgr(10, 2500, 45)
#> Warning in sgr(10, 2500, 45): some final weights are > 100 x the initial weight: grams instead of kg?
#> [1] 12.26991

Returning several results: listsRenvoyer plusieurs résultats : les listes

A function returns one object. To return several results of different types, put them in a list (an object that can hold anything) and access the parts with $.

Une fonction renvoie un seul objet. Pour renvoyer plusieurs résultats de types différents, mettez-les dans une liste (un objet qui peut tout contenir) et accédez aux éléments avec $.

farm_report <- function(d) {
  list(n_lines     = nrow(d),
       loss_pct    = round(100 * mean(d$status != "harvested"), 1),
       harvest_t   = round(sum(d$final_weight_kg, na.rm = TRUE) / 1000, 2),
       best_farmer = names(which.max(tapply(d$sgr, d$farmer_id, mean, na.rm = TRUE))))
}
r <- farm_report(seaweed[seaweed$village == "Lovobe", ])
r

#> [1] 13.6
#>

#> [1] 10.61
#> 
#> $best_farmer
#> [1] "F034"
r$harvest_t
#> [1] 10.61

Applying a function to each groupAppliquer une fonction à chaque groupe

Your functions work everywhere a built-in function works: in tapply(), sapply(), aggregate(), summarise().

Vos fonctions marchent partout où marche une fonction intégrée : dans tapply(), sapply(), aggregate(), summarise().

se <- function(x) sd(x, na.rm = TRUE) / sqrt(sum(!is.na(x)))
round(tapply(seaweed$sgr, seaweed$technique, se), 4)
#>  long-line off-bottom 
#>     0.0193     0.0175
# sapply over a vector of villages: one call of farm_report() each
sapply(c("Lovobe", "Mahavelo", "Befasy"),
       function(v) farm_report(seaweed[seaweed$village == v, ])$harvest_t)
#>   Lovobe Mahavelo   Befasy 
#>    10.61    19.81     7.38
library(dplyr)
seaweed %>% group_by(zone) %>% summarise(mean = mean(sgr, na.rm = TRUE), se = se(sgr))
#> # A tibble: 3 × 3
#>   zone    mean     se
#>   <chr>  <dbl>  <dbl>
#> 1 Centre  3.39 0.0255
#> 2 North   3.38 0.0230
#> 3 South   3.55 0.0231

Keeping your functions in a fileRanger ses fonctions dans un fichier

Put your functions in scripts/functions.R (with comments explaining each argument), and start every analysis script with source("scripts/functions.R"). You build your own small toolbox, reused from project to project.

Mettez vos fonctions dans scripts/functions.R (avec des commentaires expliquant chaque argument), et commencez chaque script d’analyse par source("scripts/functions.R"). Vous construisez votre propre petite boîte à outils, réutilisée d’un projet à l’autre.

# scripts/functions.R ----------------------------------------------------------
# sgr(): specific growth rate in % per day
#   w_initial, w_final: weights (same unit); days: duration
sgr <- function(w_initial, w_final, days) 100 * log(w_final / w_initial) / days

# se(): standard error of the mean, ignoring NA
se <- function(x) sd(x, na.rm = TRUE) / sqrt(sum(!is.na(x)))
